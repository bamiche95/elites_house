# LushTresses

A production-ready luxury hair e-commerce storefront — 100% Remy human hair bundles, HD lace
wigs, closures, frontals and accessories — built as a single Next.js 15 App Router application
with a full admin back office, guest & account checkout, Stripe/PayPal payments, transactional
email, CMS-managed editorial pages and an installable PWA.

```
Next.js 15 (App Router) · React 19 · TypeScript 5.9 · Tailwind CSS 4
Prisma 6 + PostgreSQL (Prisma Postgres) · NextAuth 4 (JWT + Prisma adapter)
Stripe + PayPal · Resend / SendGrid · Zustand · Zod · @ducanh2912/next-pwa
```

## What's included

**Storefront**

- Editorial homepage (hero, collections, best sellers, testimonials, newsletter, trust badges).
- Shop with category routes (`/shop`, `/shop/[category]`), faceted filters (texture, length,
  price, availability), sorting and pagination — all URL-driven and server-rendered.
- Product pages with variant selector (length/density), live stock, gallery, reviews, related
  products, JSON-LD `Product` + `BreadcrumbList` structured data.
- Client cart (Zustand + `localStorage`) holding only `variantId` + quantity; every price,
  stock check, coupon and shipping figure is re-validated server-side at checkout.
- Coupon codes, free-shipping threshold (£150), Standard/Express delivery options.
- Search (`/api/products?q=`), PWA install prompt, offline fallback page.

**Checkout & accounts**

- Guest checkout — a `User` row is created with `passwordHash = null` and a single-use
  SHA-256 setup token (48h TTL) is emailed so the buyer can claim the account later via
  `/guest-setup/[token]`.
- Signed-in checkout, saved addresses, order history and order detail with tracking.
- Credentials (bcrypt) + optional Google OAuth, password change, marketing preferences,
  one-click unsubscribe tokens.
- Stripe Payment Element (card, Apple Pay, Google Pay), PayPal Buttons and a
  development-only "Pay in test mode" method (hard-blocked when `NODE_ENV=production`).

**Admin back office** (`/admin`, role-gated)

- Dashboard KPIs, recent orders, low-stock alerts, "release expired stock" action.
- Orders: filter/search, status transitions (processing → dispatched → completed, cancel,
  refund) that send customer emails, tracking number capture.
- Products: create/edit, variants with per-length stock & pricing, images, categories,
  featured/best-seller flags, soft delete.
- Customers: list + detail (orders, spend, marketing opt-in).
- Content: tabbed CMS for pages (markdown), banners, FAQs, testimonials, review moderation
  and the contact inbox.
- Emails: editable brand templates plus a campaign sender (segment by opted-in customers or
  newsletter subscribers, capped per run, unsubscribe link injected automatically).

**Platform**

- SEO: metadata factory, canonicals, Open Graph/Twitter images, `sitemap.xml`, `robots.txt`,
  Organization/WebSite/Product/FAQ/Breadcrumb JSON-LD.
- PWA: web app manifest, Workbox service worker, offline page, runtime caching for remote
  images and postcode lookups.
- Security: security headers, rate limiting on auth/checkout/newsletter/contact routes,
  Zod-validated inputs, server-side authorisation on every admin action, webhook signature
  verification, idempotent payment fulfilment.

## Quick start

```bash
# 1. Install dependencies (Prisma client is generated by postinstall)
npm install

# 2. Configure the environment
cp .env.example .env          # Windows: copy .env.example .env
#    → set DATABASE_URL / DIRECT_URL and NEXTAUTH_SECRET (see below)

# 3. Create the schema and load the demo catalogue
npm run db:deploy             # prisma migrate deploy
npm run db:seed               # 18 products, 84 variants, CMS pages, coupons, users

# 4. (optional) regenerate the icon + editorial artwork in /public
npm run icons

# 5. Run it
npm run dev                   # http://localhost:3000
```

Generate a secret with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## Environment variables

Everything except the database URL, `NEXTAUTH_SECRET` and `NEXTAUTH_URL` is optional — the UI
gracefully hides integrations that are not configured. Values live in `.env` locally and in
Vercel → Settings → Environment Variables in production.

### Core (required)

| Variable          | Notes                                                                    |
| ----------------- | ------------------------------------------------------------------------ |
| `DATABASE_URL`    | PostgreSQL connection string (Prisma Postgres, Neon, Supabase, RDS…).    |
| `DIRECT_URL`      | Optional non-pooled URL used by `prisma migrate`. Defaults to the above. |
| `NEXTAUTH_SECRET` | 32-byte random string used to sign JWTs and email/verify tokens.         |
| `NEXTAUTH_URL`    | Public origin, e.g. `https://lushtresses.com` (no trailing slash).       |

### Auth

| Variable               | Notes                                                    |
| ---------------------- | -------------------------------------------------------- |
| `GOOGLE_CLIENT_ID`     | Optional. The Google button hides when unset.            |
| `GOOGLE_CLIENT_SECRET` | Redirect URI: `{NEXTAUTH_URL}/api/auth/callback/google`. |

### Payments

| Variable                             | Notes                                                      |
| ------------------------------------ | ---------------------------------------------------------- |
| `STRIPE_SECRET_KEY`                  | Enables the card / Apple Pay / Google Pay tab.             |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Client-side Stripe key.                                    |
| `STRIPE_WEBHOOK_SECRET`              | From `stripe listen` or the Stripe Dashboard webhook.      |
| `NEXT_PUBLIC_PAYPAL_CLIENT_ID`       | Enables the PayPal tab.                                    |
| `PAYPAL_CLIENT_SECRET`               | Server-side PayPal credentials.                            |
| `PAYPAL_WEBHOOK_ID`                  | Webhook ID used to verify `PAYPAL-TRANSMISSION-*` headers. |
| `PAYPAL_ENV`                         | `sandbox` (default) or `live`.                             |
| `ALLOW_DEMO_PAYMENTS`                | `true` enables "Pay in test mode" — **development only**.  |

### Email

| Variable                   | Notes                                                       |
| -------------------------- | ----------------------------------------------------------- |
| `EMAIL_PROVIDER`           | `resend` (default) or `sendgrid`.                           |
| `RESEND_API_KEY`           | Required when `EMAIL_PROVIDER=resend`.                      |
| `SENDGRID_API_KEY`         | Required when `EMAIL_PROVIDER=sendgrid`.                    |
| `EMAIL_FROM`               | Verified sender, e.g. `LushTresses <hello@lushtresses.com>`.|
| `ADMIN_NOTIFICATION_EMAIL` | Receives new-order and contact-form notifications.          |

When no provider is configured every send is logged to `EmailLog` with status `SKIPPED`, so the
flows stay testable without pretending an email went out.

### Site & operations

| Variable                       | Notes                                                       |
| ------------------------------ | ----------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`         | Canonical origin used for metadata, sitemap and links.       |
| `NEXT_PUBLIC_BRAND_NAME`       | Brand name shown in the header, footer and emails.           |
| `NEXT_PUBLIC_SUPPORT_EMAIL`    | Public support address.                                     |
| `NEXT_PUBLIC_SUPPORT_PHONE`    | Public support number.                                      |
| `NEXT_PUBLIC_INSTAGRAM_URL`    | Footer social link.                                         |
| `CRON_SECRET`                  | Bearer token protecting `/api/cron/expire-orders`.           |
| `SEED_ADMIN_*`                 | Admin email/password written by `npm run db:seed`.           |
| `SEED_CUSTOMER_*`              | Demo customer email/password written by `npm run db:seed`.   |

## Database & migrations

Any PostgreSQL 14+ works. With **Prisma Postgres** (the default for this project):

1. Create a project at [console.prisma.io](https://console.prisma.io) and copy the connection
   string from the *Connect* panel.
2. Set `DATABASE_URL` to the pooled connection string and `DIRECT_URL` to the direct one.
3. Run `npm run db:deploy` (or `npm run db:migrate` locally to create new migrations).

```
prisma/
├── schema.prisma                 # single source of truth (27 models, enums, indices)
├── migrations/
│   ├── 00000000000000_init/      # baseline migration generated from the schema
│   └── migration_lock.toml
└── seed.ts                       # catalogue, CMS, coupons, FAQ, testimonials, users
```

> **Existing database created with `prisma db push`?** Baseline it once so migrations stay in
> sync: `npx prisma migrate resolve --applied 00000000000000_init`.

Model highlights:

- `Product` → `ProductVariant` (length × density, per-variant `stock` and `pricePence`),
  `ProductImage`, `ProductCategory`.
- `Order` → `OrderItem`, `OrderEvent` (human-readable audit trail) and
  `PaymentTransaction`. The unique `PaymentTransaction.providerRef` is what makes payment
  fulfilment idempotent: a retried webhook can never apply the same capture twice.
- `User` (+ `AccountSetupToken`, `Address`, `Review`, `EmailLog`), `Coupon`,
  `NewsletterSubscriber`, `Page`, `Banner`, `Faq`, `Testimonial`, `ContactMessage`,
  `EmailTemplate`, `EmailCampaign`.

Money is stored as **integer pence** everywhere (`9500` = £95.00) — never floats.

## Payments

The checkout flow is identical for every provider:

1. `POST /api/checkout/start` re-prices the cart from the database (never trusting the client),
   validates stock with an optimistic guard, reserves inventory, creates the `Order` +
   `OrderEvent("ORDER_CREATED")` and returns the provider payload.
2. The browser completes payment with the provider's SDK.
3. Fulfilment happens **only** in a webhook (or the demo endpoint) via `markOrderPaid()`, which
   flips the order to `PAID`/`PROCESSING`, writes a `PaymentTransaction` and emails the customer.

| Provider | Client                                 | Server confirmation                    |
| -------- | -------------------------------------- | -------------------------------------- |
| Stripe   | Payment Element (card/wallet)          | `/api/webhooks/stripe` + `/api/checkout/stripe-confirm` |
| PayPal   | `@paypal/react-paypal-js` buttons      | `/api/checkout/paypal-capture` + `/api/webhooks/paypal` |
| Demo     | "Pay in test mode" (dev only)          | `POST /api/checkout/demo`              |

Unpaid orders are released automatically: `expireStaleOrders(hours = 2)` returns the reserved
stock and cancels the order. It runs from `/api/cron/expire-orders` and from the "Release
expired stock" button on the admin dashboard.

### Local card testing

stripe listen --forward-to localhost:3000/api/webhooks/stripe

## Webhooks

| Endpoint                | Signature verification                                     |
| ----------------------- | ---------------------------------------------------------- |
| `/api/webhooks/stripe`  | `stripe.webhooks.constructEvent` with `STRIPE_WEBHOOK_SECRET`. Handles `payment_intent.succeeded`, `payment_intent.payment_failed`, `charge.refunded`. |
| `/api/webhooks/paypal`  | `verify-webhook-signature` against `PAYPAL_WEBHOOK_ID`.     |

Both endpoints are `force-dynamic`, return `2xx` quickly and are safe to retry — duplicate
deliveries are absorbed by the unique `PaymentTransaction.providerRef` and by an early
`paymentStatus === "PAID"` check.

## Email

- Provider abstraction: `src/lib/email/send.ts` (**Resend** by default, **SendGrid** when
  `EMAIL_PROVIDER=sendgrid`), `src/lib/email/templates.ts` for branded HTML. Every send is
  persisted to `EmailLog` with its status (`SENT`, `SKIPPED`, `FAILED`).
- Transactional emails: order confirmation, order status updates (processing, dispatched,
  completed, cancelled/refunded), guest account setup + reminder, welcome, admin new-order
  alert and the contact-form acknowledgement.
- Campaigns: **Admin → Emails → Campaigns** sends to `marketingOptIn` users or active newsletter
  subscribers (max 200 per run), records `EmailCampaign` counters, and injects the
  `unsubscribeToken` link.
- Copy for brand emails can be edited in **Admin → Emails → Templates** (`EmailTemplate`).

## Stock expiry cron

`vercel.json` schedules `/api/cron/expire-orders` every 30 minutes:

```json
{ "crons": [{ "path": "/api/cron/expire-orders", "schedule": "*/30 * * * *" }] }
```

- Vercel sends `Authorization: Bearer $CRON_SECRET` automatically once `CRON_SECRET` is set.
- In production the route returns `503` when `CRON_SECRET` is missing, so the job can never be
  triggered anonymously.
- Vercel **Hobby** plans only allow daily crons — change the schedule to `0 3 * * *` (or use an
  external scheduler) if you deploy on Hobby.
- On other hosts simply call the URL from cron/systemd with the same header.

## Admin guide

The back office lives at `/admin` and is gated twice: `src/middleware.ts` checks the JWT
(signed-out → `/login?callbackUrl=/admin`, non-admin → `/account?error=forbidden`) and
`requireAdmin()` re-verifies the role on the server before any data is read or mutated.

| Section  | What you can do                                                                 |
| -------- | ------------------------------------------------------------------------------- |
| Overview | Revenue/orders/customers KPIs, recent orders, low-stock list, one-click "release expired stock". |
| Orders   | Search & filter, open an order to change status, add tracking, cancel/refund; every change is logged as an `OrderEvent` and emails the customer. |
| Products | Create/edit products, variants (length × density stock & price), images, category, featured/best-seller flags, activate/deactivate. |
| Customers| Browse customers, open a profile for their orders, spend and marketing opt-in.   |
| Content  | Tabs for Pages (markdown + SEO), Banners, FAQs, Testimonials, Reviews (approve/publish) and the contact Inbox. |
| Emails   | Templates (copy for brand emails) and Campaigns (send to opted-in customers or newsletter subscribers). |

All admin mutations are React Server Actions that take `FormData`, re-check the session, and
revalidate the affected paths — there are no unprotected admin API routes.

## Deploying to Vercel

1. **Push the repository** to GitHub/GitLab and import it in Vercel. The Next.js preset is
   detected automatically; `vercel.json` pins the build command
   (`prisma generate && next build`) and the expiry cron.
2. **Add environment variables** (Project → Settings → Environment Variables) — copy
   `.env.example` and set at least:

   ```
   DATABASE_URL, DIRECT_URL, NEXTAUTH_SECRET, NEXTAUTH_URL=https://your-domain
   NEXT_PUBLIC_SITE_URL=https://your-domain, CRON_SECRET
   ```

   Add Stripe/PayPal/email keys if you use them. Keep `ALLOW_DEMO_PAYMENTS` unset in
   production (it is ignored there anyway).
3. **Migrate the production database** once, from your machine, against the production URL:

   ```bash
   $env:DATABASE_URL="postgres://…"; $env:DIRECT_URL="postgres://…"
   npm run db:deploy
   # optional demo catalogue:
   npm run db:seed
   ```

   Or add `prisma migrate deploy` to your CI pipeline before the deploy step.
4. **Point the providers at the live domain**

   | Provider | Setting                                                                 |
   | -------- | ----------------------------------------------------------------------- |
   | Stripe   | Webhook `https://your-domain/api/webhooks/stripe` → `payment_intent.succeeded`, `payment_intent.payment_failed`, `charge.refunded`; paste the signing secret into `STRIPE_WEBHOOK_SECRET`. |
   | PayPal   | Webhook URL `https://your-domain/api/webhooks/paypal`; paste its ID into `PAYPAL_WEBHOOK_ID`; set `PAYPAL_ENV=live`. |
   | Google   | Authorised redirect URI `https://your-domain/api/auth/callback/google`. |
   | Email    | Verify the sending domain at Resend/SendGrid and update `EMAIL_FROM`.   |

5. **Deploy**, then verify `/manifest.webmanifest`, `/sw.js`, `/sitemap.xml` and
   `/robots.txt` resolve on the live domain. The service worker is regenerated on every build.
6. **Harden**: sign in as the admin and change the seeded password, set `CRON_SECRET`, confirm
   the cron appears under Project → Cron Jobs, and add the domain in Vercel → Domains.

Notes

- The app runs on the Node.js runtime (Prisma needs it); no Edge-only data access is used.
- `images.remotePatterns` in `next.config.ts` whitelists Unsplash, Cloudinary and Google
  avatars — add your own CDN host before pasting those URLs into the CMS.
- Vercel builds run `postinstall` (`prisma generate`), so the client is always available.

## Smoke-test checklist

A five-minute pass that exercises the money paths (all verified against a seeded database):

1. `npm run dev` → `/`, `/shop`, `/shop/bundles`, a product page, `/cart`, `/faq`, `/about`,
   `/shipping`, `/returns`, `/privacy`, `/terms`, `/hair-care`, `/gift-cards`,
   `/payment-info`, `/contact`, `/login`, `/register` all render `200`.
2. Shop → filter by texture/length → sort → paginate; open a product, pick a length, add to bag.
3. Cart: change qty, apply a seeded coupon, see the free-shipping threshold behave.
4. Checkout as a guest with **Pay in test mode** → order confirmation page → order appears in
   `/account/orders` and in **Admin → Orders** as `PAID`/`PROCESSING`, variant stock decremented.
5. The confirmation email (or `EmailLog` row) carries the guest account setup link
   (`/guest-setup/[token]`) — open it, set a password, land in `/account`.
6. Admin: change the order to *Dispatched* with a tracking number → customer email + `OrderEvent`;
   "Release expired stock" cancels stale unpaid orders.
7. Admin → Emails: save a template, run a campaign (logged as `SKIPPED` when no provider key).
8. Lighthouse/PWA: install prompt appears, offline page loads, `/sitemap.xml` lists products and
   CMS pages.

## Troubleshooting

| Symptom | Fix |
| ------- | --- |
| `Environment variable not found: DATABASE_URL` | Create `.env` from `.env.example` (Prisma reads it from the repo root); on Vercel set the variable and redeploy. |
| `prisma migrate deploy` fails with *relation already exists* (`P3005`) | The database was created with `db push`. Baseline it once: `npx prisma migrate resolve --applied 00000000000000_init`, then re-run `db:deploy`. |
| `[next-auth][error][NO_SECRET]` or sessions silently drop | `NEXTAUTH_SECRET` is missing or shorter than 32 bytes. |
| Login succeeds then bounces to `/login` | `NEXTAUTH_URL` must match the exact origin (including `https://` in production, no trailing slash). Clear cookies afterwards. |
| "Continue with Google" is missing | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` are unset — the button is hidden by design. |
| Card or PayPal tabs are missing at checkout | Stripe/PayPal keys are unset; the "Pay in test mode" method only appears in development. |
| Emails never arrive | `EmailLog` shows `SKIPPED` when no provider key is configured (`RESEND_API_KEY` or `SENDGRID_API_KEY` + `EMAIL_FROM`). Check spam and domain verification too. |
| `/api/cron/expire-orders` returns `401`/`503` | Set `CRON_SECRET` and send `Authorization: Bearer <secret>` (Vercel does this for you). |
| `next/image` returns `400` for a pasted image URL | Add the host to `images.remotePatterns` in `next.config.ts`. |
| Stale service worker after a deploy | Dev builds disable the SW. In production, hard-reload or unregister it (DevTools → Application → Service Workers); the SW is regenerated per build with `cleanupOutdatedCaches`. |
| Types complain about missing Prisma fields | `npm run db:generate` after editing `prisma/schema.prisma`. |
| `next lint` warns that the command is deprecated | Expected on Next 15 — the ESLint config still runs; Next 16 will require the ESLint CLI. |
