# The Elites House

A production-ready luxury hair e-commerce storefront — 100% Remy human hair bundles, HD lace
wigs, closures, frontals and accessories — built as a single Next.js 15 App Router application
with a full admin back office, guest & account checkout, Stripe/PayPal payments, transactional
email, CMS-managed editorial pages and an installable PWA.

```
Next.js 15 (App Router) · React 19 · TypeScript 5.9 · Tailwind CSS 4
Prisma 6 + PostgreSQL (Prisma Postgres) · NextAuth 4 (JWT + Prisma adapter)
Stripe + PayPal · SMTP (nodemailer) / Resend / SendGrid · Zustand · Zod · @ducanh2912/next-pwa
```

## What's included

**Storefront**

- Editorial homepage (hero, collections, best sellers, testimonials, newsletter, trust badges).
- Shop with category routes (`/shop`, `/shop/[category]`), faceted filters (texture, length,
  price, availability), sorting and pagination — all URL-driven and server-rendered.
- Product pages with variant selector (length/density), live stock, gallery, reviews, related
  products, JSON-LD `Product` + `BreadcrumbList` structured data.
- Client cart (Zustand + `localStorage`) holding only `variantId` + quantity; every price,
  stock check, coupon and shipping figure is re-validated server-side at checkout.
- Coupon codes, free-shipping threshold (£150), Standard/Express delivery options.
- Search (`/api/products?q=`), PWA install prompt, offline fallback page.

**Checkout & accounts**

- Guest checkout — a `User` row is created with `passwordHash = null` and a single-use
  SHA-256 setup token (48h TTL) is emailed so the buyer can claim the account later via
  `/guest-setup/[token]`.
- Signed-in checkout, saved addresses, order history and order detail with tracking.
- Credentials (bcrypt) + optional Google OAuth, password change, marketing preferences,
  one-click unsubscribe tokens.
- Stripe Payment Element with a tile for each method enabled in the default Stripe
  Payment Method Configuration (Card, Klarna, PayPal, Revolut Pay, Amazon Pay, Pay by Bank),
  PayPal Buttons and a development-only "Test payment" method (hard-blocked when
  `NODE_ENV=production`).

**Admin back office** (`/admin`, role-gated)

- Dashboard KPIs, recent orders, low-stock alerts, "release expired stock" action.
- Orders: filter/search, status transitions (processing → dispatched → completed, cancel,
  refund) that send customer emails, tracking number capture.
- Products: create/edit, variants with per-length stock & pricing, multi-image gallery uploads,
  categories, featured/best-seller flags, soft delete.
- Customers: list + detail (orders, spend, marketing opt-in).
- Content: tabbed CMS for pages (markdown), banners, FAQs, testimonials, review moderation
  and the contact inbox.
- Emails: editable brand templates plus a campaign sender (segment by opted-in customers or
  newsletter subscribers, capped per run, unsubscribe link injected automatically).

**Platform**

- SEO: metadata factory, canonicals, Open Graph/Twitter images, `sitemap.xml`, `robots.txt`,
  Organization/WebSite/Product/FAQ/Breadcrumb JSON-LD.
- PWA: web app manifest, Workbox service worker, offline page, runtime caching for remote
  images and postcode lookups.
- Security: security headers, rate limiting on auth/checkout/newsletter/contact routes,
  Zod-validated inputs, server-side authorisation on every admin action, webhook signature
  verification, idempotent payment fulfilment.

## Quick start

```bash
# 1. Install dependencies (Prisma client is generated by postinstall)
npm install

# 2. Configure the environment
cp .env.example .env          # Windows: copy .env.example .env
#    → set DATABASE_URL / DIRECT_URL and NEXTAUTH_SECRET (see below)

# 3. Create the schema and load the demo catalogue
npm run db:deploy             # prisma migrate deploy
npm run db:seed               # 18 products, 84 variants, CMS pages, coupons, users

# 4. (optional) regenerate the icon + editorial artwork in /public
npm run icons

# 5. Run it
npm run dev                   # http://localhost:3000
```

Generate a secret with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### Seeded logins

| Role     | Email                   | Password         |
| -------- | ----------------------- | ---------------- |
| Admin    | `admin@theeliteshouse.com` | `LushAdmin2026!` |
| Customer | `customer@example.com`  | `LushCustomer2026!` |

Override these with `SEED_ADMIN_*` / `SEED_CUSTOMER_*` **before** seeding. The defaults are in this
repo, so change the admin password on every real deployment — from Account → Settings while signed
in, or from the terminal (masked prompt, 12+ characters, refuses the documented default):

```bash
npm run admin:password -- --email you@domain.com              # rotate an existing account
npm run admin:password -- --email new@domain.com --create     # add a second admin
npm run admin:password -- --email you@domain.com --password '…'   # scripted / CI (or ADMIN_NEW_PASSWORD)
```

The script writes straight to `DATABASE_URL` with bcrypt cost 12, so it also works when nobody can
sign in. Add `--promote` to turn an existing CUSTOMER account into an admin.

### Email

| Variable                   | Notes                                                       |
| -------------------------- | ----------------------------------------------------------- |
| `EMAIL_PROVIDER`           | `smtp`, `resend` (default) or `sendgrid`.                   |
| `SMTP_HOST`                | Mail server host, e.g. `premium709.web-hosting.com`.        |
| `SMTP_PORT`                | `465` (SSL, the default) or `587` (STARTTLS).               |
| `SMTP_SECURE`              | `true` for port 465; set `false` for 587/STARTTLS.          |
| `SMTP_USER`                | Full mailbox address used for auth, e.g. `orders@theeliteshouse.com`.|
| `SMTP_PASSWORD`            | Mailbox password (quote it if it contains `#`).             |
| `RESEND_API_KEY`           | Required when `EMAIL_PROVIDER=resend`.                      |
| `SENDGRID_API_KEY`         | Required when `EMAIL_PROVIDER=sendgrid`.                    |
| `EMAIL_FROM`               | Envelope/visible sender, e.g. `The Elites House <orders@theeliteshouse.com>`.|
| `ADMIN_NOTIFICATION_EMAIL` | Receives new-order alerts, e.g. `orders@theeliteshouse.com`.|

With `EMAIL_PROVIDER=smtp` the app sends through your hosting mailbox over nodemailer, so no
third-party ESP is needed. Most cPanel/Exim servers require the `From` address to belong to the
authenticated mailbox — keep `EMAIL_FROM` and `SMTP_USER` on the same address (the default pair is
`orders@theeliteshouse.com`), and use `Reply-To` for the support inbox. Run `npm run email:check`
to verify the login and deliver a test message before trusting a new mailbox.

When no provider is configured every send is logged to `EmailLog` with status `SKIPPED`, so the
flows stay testable without pretending an email went out.

## Database & migrations

Any PostgreSQL 14+ works. With **Prisma Postgres** (the default for this project):

1. Create a project at [console.prisma.io](https://console.prisma.io) and copy the connection
   string from the *Connect* panel.
2. Set `DATABASE_URL` to the pooled connection string and `DIRECT_URL` to the direct one.
3. Run `npm run db:deploy` (or `npm run db:migrate` locally to create new migrations).

```
prisma/
├── schema.prisma                 # single source of truth (27 models, enums, indices)
├── migrations/
│   ├── 00000000000000_init/      # baseline migration generated from the schema
│   └── migration_lock.toml
└── seed.ts                       # catalogue, CMS, coupons, FAQ, testimonials, users
```

> **Existing database created with `prisma db push`?** Baseline it once so migrations stay in
> sync: `npx prisma migrate resolve --applied 00000000000000_init`.

Model highlights:

- `Product` → `ProductVariant` (length × density, per-variant `stock` and `pricePence`),
  `ProductImage`, `ProductCategory`.
- `Order` → `OrderItem`, `OrderEvent` (human-readable audit trail) and
  `PaymentTransaction`. The unique `PaymentTransaction.providerRef` is what makes payment
  fulfilment idempotent: a retried webhook can never apply the same capture twice.
- `User` (+ `AccountSetupToken`, `Address`, `Review`, `EmailLog`), `Coupon`,
  `NewsletterSubscriber`, `Page`, `Banner`, `Faq`, `Testimonial`, `ContactMessage`,
  `EmailTemplate`, `EmailCampaign`.

Money is stored as **integer pence** everywhere (`9500` = £95.00) — never floats.

## Payments

The checkout flow is identical for every provider:

1. `POST /api/checkout/start` re-prices the cart from the database (never trusting the client),
   validates stock with an optimistic guard, reserves inventory, creates the `Order` +
   `OrderEvent("ORDER_CREATED")` and returns the provider payload.
2. The browser completes payment with the provider's SDK.
3. Fulfilment happens **only** in a webhook (or the demo endpoint) via `markOrderPaid()`, which
   flips the order to `PAID`/`PROCESSING`, writes a `PaymentTransaction` and emails the customer.

| Provider | Client                                 | Server confirmation                    |
| -------- | -------------------------------------- | -------------------------------------- |
| Stripe   | Payment Element (selected method)      | `/api/webhooks/stripe` + `/api/checkout/stripe-confirm` |
| PayPal   | `@paypal/react-paypal-js` buttons      | `/api/checkout/paypal-capture` + `/api/webhooks/paypal` |
| Demo     | "Test payment" (dev only)              | `POST /api/checkout/demo`              |

Unpaid orders are released automatically: `expireStaleOrders(hours = 2)` returns the reserved
stock and cancels the order. It runs from `/api/cron/expire-orders` and from the "Release
expired stock" button on the admin dashboard.

### Local card testing

Payments use the Stripe **test** keys (`sk_test_…` / `pk_test_…`). Use card
`4242 4242 4242 4242`, any future expiry and any CVC (declines: `4000 0000 0000 0002`).
Checkout reads the root default **Payment Method Configuration** from the Stripe
Dashboard and renders a tile for each supported method that is enabled: Card, Klarna,
PayPal, Revolut Pay, Amazon Pay and Pay by Bank. Toggle them under **Settings → Payments
→ Payment methods**; the server cache refreshes every 10 seconds in development and
5 minutes in production. Redirect methods return to `/checkout/success?order=…`, where
`StripeConfirm` verifies the PaymentIntent.

Fulfilment happens in two independent places, so a card payment is marked paid even
without a webhook listener: `POST /api/checkout/stripe-confirm` (called by the success
page) and `/api/webhooks/stripe`. Both funnel into `markOrderPaid()`, so a duplicate
delivery is absorbed.

To exercise the **signed webhook** you need `STRIPE_WEBHOOK_SECRET` set. Locally any
`whsec_…` string works — the signature is only ever checked against that value:

```bash
# Option A – real Stripe events (needs the Stripe CLI: https://stripe.com/docs/stripe-cli)
npm run stripe:listen            # prints whsec_… — paste it into .env, restart `npm run dev`

# Option B – no CLI: simulate the card charge *and* the webhook
# 1. STRIPE_WEBHOOK_SECRET="whsec_local_dev" in .env, then restart `npm run dev`
# 2. add to bag → continue to payment → choose Card → copy the order reference
npm run stripe:simulate -- LT-2611-ABCDE succeeded   # pays with pm_card_visa
npm run stripe:simulate -- LT-2611-ABCDE failed      # pm_card_chargeDeclined → PAYMENT_FAILED
```

The simulator confirms the existing PaymentIntent with a Stripe test payment method,
signs the resulting `payment_intent.*` event with your webhook secret and posts it to
`/api/webhooks/stripe` — the same code path production uses. Leave
`STRIPE_WEBHOOK_SECRET` empty if you don't need it: the endpoint then answers `503`
instead of accepting unsigned events.

## Webhooks

| Endpoint                | Signature verification                                     |
| ----------------------- | ---------------------------------------------------------- |
| `/api/webhooks/stripe`  | `stripe.webhooks.constructEvent` with `STRIPE_WEBHOOK_SECRET`. Handles `payment_intent.succeeded`, `payment_intent.payment_failed`, `charge.refunded`. |
| `/api/webhooks/paypal`  | `verify-webhook-signature` against `PAYPAL_WEBHOOK_ID`.     |

Both endpoints are `force-dynamic`, return `2xx` quickly and are safe to retry — duplicate
deliveries are absorbed by the unique `PaymentTransaction.providerRef` and by an early
`paymentStatus === "PAID"` check.

## Email

- Provider abstraction: `src/lib/email/send.ts` — **SMTP** via nodemailer (`EMAIL_PROVIDER=smtp`),
  **Resend** (default) or **SendGrid** (`EMAIL_PROVIDER=sendgrid`) — plus
  `src/lib/email/templates.ts` for branded HTML. Every send is persisted to `EmailLog` with its
  status (`SENT`, `SKIPPED`, `FAILED`).
- Addresses: everything is sent from `EMAIL_FROM` (`orders@theeliteshouse.com`), because the SMTP
  mailbox authenticates as that address. New-order and contact alerts go to
  `ADMIN_NOTIFICATION_EMAIL` (`orders@`); contact-form mail goes to `contact@` with the customer as
  `Reply-To`, so replies land in the support inbox. Public support copy uses
  `NEXT_PUBLIC_CONTACT_EMAIL` (`contact@`), and returns/gift-card copy uses
  `NEXT_PUBLIC_ORDERS_EMAIL` (`orders@`).
- `npm run email:check [inbox]` logs into the SMTP server, reports the greeting/certificate result
  and delivers one test message — the quickest way to prove a mailbox before blaming the app.
- `npm run email:check -- --dns` reports **MX / SPF / DKIM / DMARC** for the `EMAIL_FROM` domain, the
  address behind `mail.<domain>`, and then opens an SMTP conversation with every MX to confirm it
  greets and accepts `NEXT_PUBLIC_CONTACT_EMAIL`; it exits non-zero when any of that is wrong. A
  mailbox can authenticate and still be unreachable: without **MX** nothing on the internet can
  deliver to `contact@` / `orders@`, and without **SPF + DKIM (+ DMARC)** Gmail/Outlook treat outbound
  mail as forged and spam-file or reject it. The zone lives wherever the nameservers point (Vercel DNS
  for this project), *not* at the mail host — and not in the registrar's zone editor, which goes inert
  the moment the nameservers are delegated elsewhere. Shared hosting
  (`premium709.web-hosting.com`) receives mail through the provider's relay cluster
  (`mx*-hosting.jellyfish.systems`), so MX must target those relays: the web server itself never
  greets on port 25, and an MX pointed at it makes every delivery time out.
- Transactional emails: order confirmation, order status updates (processing, dispatched,
  completed, cancelled/refunded), guest account setup + reminder, welcome, admin new-order
  alert and the contact-form acknowledgement.
- Campaigns: **Admin → Emails → Campaigns** sends to `marketingOptIn` users or active newsletter
  subscribers (max 200 per run), records `EmailCampaign` counters, and injects the
  `unsubscribeToken` link.
- Copy for brand emails can be edited in **Admin → Emails → Templates** (`EmailTemplate`).

## Media & uploads

Product galleries, banner artwork, CMS page heroes and testimonial photos are uploaded from the
admin and stored in **Vercel Blob** (production) or on disk (development).

- Storage adapter: `src/lib/media/storage.ts`. `BLOB_READ_WRITE_TOKEN` present → `@vercel/blob`
  `put()` under a `<folder>/<uuid>.<ext>` key; otherwise `public/uploads/<folder>/` (dev only —
  production refuses the disk fallback with a `503`). `MEDIA_PROVIDER` forces either adapter.
- Upload endpoint: `POST /api/admin/uploads` (`runtime = "nodejs"`), one file per request with
  `folder` = `products | banners | pages | testimonials`. Auth is re-checked server-side
  (`401` signed out, `403` non-admin) and limited to 40 uploads/minute per admin.
  `DELETE /api/admin/uploads?url=…` removes an asset that never reached the database.
- Validation (`src/lib/media/validate.ts`) happens on the bytes, not the file name: magic-number
  sniffing for **JPEG, PNG, WebP and AVIF** only, 4 MB per file (below Vercel's ~4.5 MB body cap).
  Renamed executables and SVGs are rejected (`422`) — SVG is a stored-XSS vector.
- Product galleries (`ProductImages` rows, `position` = gallery order) are edited in
  **Admin → Products → {product} → Gallery** with `src/components/admin/product-images-manager.tsx`:
  upload/drop several files (they upload sequentially, one request each), reorder, star an image as
  primary, edit alt text and delete. Every change persists immediately through
  `saveProductImagesAction` → `applyProductImages()` (one transaction of create/update/delete, then
  the dropped files are removed from the store and `/product/[slug]`, `/shop` and `/` revalidate).
  Index 0 is the primary image used by cards, the cart and order emails.
- Single-image fields use `src/components/admin/image-uploader.tsx`, which keeps the URL in a hidden
  input so the existing banner/page/testimonial server actions stay unchanged. Replacing or
  deleting a record removes the previous file from the store (pasted `/images/…` and external URLs
  are left alone).
- New products can carry a full gallery before they exist: the create form submits a hidden
  `imageUrls` JSON field read by `createProductAction` (`parseImageList` drops unsafe URLs,
  duplicates and anything past 10 images).
- `next/image` needs the Blob host in `images.remotePatterns` (`*.public.blob.vercel-storage.com`,
  already configured). Uploaded keys never collide — filenames are UUIDs.
- `npm run media:check` validates the sniffing rules, the gallery diffing helpers and runs a
  real write/read/delete round-trip against whichever adapter is active.

### Turning uploads on in production

1. Vercel dashboard → **Storage → Create → Blob**, then **Connect** it to the `elites-house`
   project for all environments.
2. Redeploy (or re-run the deployment that failed) so `BLOB_READ_WRITE_TOKEN` is present.
3. Locally, run `vercel env pull .env.local` (or paste the token into `.env`) and
   `npm run media:check`.
4. `public/uploads/` is git-ignored, so local test uploads never leak into commits.

## Stock expiry cron

`vercel.json` schedules `/api/cron/expire-orders` once a day at 03:00 UTC — the cadence Vercel's
**Hobby** plan allows:

```json
{ "crons": [{ "path": "/api/cron/expire-orders", "schedule": "0 3 * * *" }] }
```

- Unpaid orders older than the expiry window are cancelled and their stock released, so a daily
  sweep is sufficient. On **Pro** you can tighten it to `0 * * * *` (hourly) or `*/30 * * * *`;
  on Hobby any sub-daily expression fails the deployment with *"Hobby plans can only run cron jobs
  once per day"*.
- Vercel sends `Authorization: Bearer $CRON_SECRET` automatically once `CRON_SECRET` is set.
- In production the route returns `503` when `CRON_SECRET` is missing, so the job can never be
  triggered anonymously.
- On other hosts simply call the URL from cron/systemd with the same header.

## Admin guide

The back office lives at `/admin` and is gated twice: `src/middleware.ts` checks the JWT
(signed-out → `/login?callbackUrl=/admin`, non-admin → `/account?error=forbidden`) and
`requireAdmin()` re-verifies the role on the server before any data is read or mutated.

| Section  | What you can do                                                                 |
| -------- | ------------------------------------------------------------------------------- |
| Overview | Revenue/orders/customers KPIs, recent orders, low-stock list, one-click "release expired stock". |
| Orders   | Search & filter, open an order to change status, add tracking, cancel/refund; every change is logged as an `OrderEvent` and emails the customer. |
| Products | Create/edit products, variants (length × density stock & price), images, category, featured/best-seller flags, activate/deactivate. |
| Customers| Browse customers, open a profile for their orders, spend and marketing opt-in.   |
| Content  | Tabs for Pages (markdown + SEO), Banners, FAQs, Testimonials, Reviews (approve/publish) and the contact Inbox. |
| Emails   | Templates (copy for brand emails) and Campaigns (send to opted-in customers or newsletter subscribers). |

All admin mutations are React Server Actions that take `FormData`, re-check the session, and
revalidate the affected paths — there are no unprotected admin API routes.

Admins are `User` rows with `role = "ADMIN"`; there is no in-app user-management screen, so add or
reset one from the terminal with `npm run admin:password -- --email … --create` (or `--promote` for
an existing customer account).

## Deploying to Vercel

The project deploys through the Vercel **Git integration**: pushes to `main` go to production, every
other branch produces a preview. `vercel.json` pins the build command
(`prisma generate && next build`), the function region (`cdg1`, next to the Paris database) and the
daily expiry cron. Import the repo once in Vercel (Add New → Project) — the Next.js preset is
detected automatically.

> **Order matters.** `/`, `/faq` and every CMS page (`/about`, `/privacy`, …) are prerendered from
> the database at build time, so an unmigrated or empty database fails the deployment with
> *"The table public.Page does not exist"*. Do step 2 before the first build.

1. **Collect the credentials.** In Prisma Postgres → *Connect* you get a pooled string (used by the
   app) and a direct one (used by migrations). Rotate the password first if an older one was shared.
2. **Migrate and seed the production database** once, from your machine, against the production
   URLs:

   ```bash
   $env:DATABASE_URL="postgres://…@pooled.db.prisma.io:5432/postgres?sslmode=require"
   $env:DIRECT_URL="postgres://…@db.prisma.io:5432/postgres?sslmode=require"
   $env:SEED_ADMIN_EMAIL="you@yourdomain.com"; $env:SEED_ADMIN_PASSWORD="<strong-password>"

   npx prisma migrate deploy    # applies prisma/migrations/00000000000000_init
   npx prisma db seed           # demo catalogue, CMS pages, email templates, accounts
   ```

   Use `migrate deploy`, not `migrate dev` — Prisma Postgres does not expose the shadow database the
   dev command needs. Create new migrations locally and commit them. The same two commands can run
   in CI ahead of the deploy step.
3. **Add environment variables** (Project → Settings → Environment Variables) for **Production and
   Preview** — copy `.env.example` and set at least:

   ```
   DATABASE_URL, DIRECT_URL, NEXTAUTH_SECRET, NEXTAUTH_URL=https://your-domain
   NEXT_PUBLIC_SITE_URL=https://your-domain, CRON_SECRET
   ```

   Add the Stripe/PayPal/email keys if you use them and leave `ALLOW_DEMO_PAYMENTS` unset ("Test
   payment" is hard-blocked in production builds). `NEXT_PUBLIC_*` values are inlined at build
   time, so redeploy after changing them.

   ```bash
   vercel link --project <your-project>
   vercel env pull .env.vercel --environment=production --yes   # sanity-check what Vercel holds
   ```
4. **Point the providers at the live domain**

   | Provider | Setting                                                                 |
   | -------- | ----------------------------------------------------------------------- |
   | Stripe   | Webhook `https://your-domain/api/webhooks/stripe` → `payment_intent.succeeded`, `payment_intent.payment_failed`, `charge.refunded`; paste the signing secret into `STRIPE_WEBHOOK_SECRET`. |
   | PayPal   | Webhook URL `https://your-domain/api/webhooks/paypal`; paste its ID into `PAYPAL_WEBHOOK_ID`; set `PAYPAL_ENV=live`. |
   | Google   | Authorised redirect URI `https://your-domain/api/auth/callback/google`. |
   | Email    | Verify the sending domain at Resend/SendGrid and update `EMAIL_FROM`.   |

5. **Deploy** by pushing to `main` and watch the build log for `prisma generate`, the route table and
   the regenerated `public/sw.js`. (`vercel deploy --prod` still works but is optional once Git is
   connected — CLI deploys bypass the Git history.) Then check `/manifest.webmanifest`, `/sw.js`,
   `/sitemap.xml`, `/robots.txt` and
   `curl -H "Authorization: Bearer $CRON_SECRET" https://your-domain/api/cron/expire-orders`
   on the live domain.
6. **Harden**: change the seeded admin password (Account → Settings, or
   `npm run admin:password -- --email you@domain.com` against the production `DATABASE_URL`), set
   `CRON_SECRET`, confirm the cron appears under Project → Cron Jobs, and add the domain in
   Vercel → Domains.

Notes

- The app runs on the Node.js runtime (Prisma needs it); no Edge-only data access is used.
- `regions: ["cdg1"]` in `vercel.json` keeps functions next to the Paris database — adjust it if
  your Prisma Postgres region differs.
- Preview deployments sit behind **Vercel Authentication**, so Stripe/PayPal webhooks can only reach
  production. They still prerender the same pages, hence Preview needs the same database variables.
- Hobby allows one cron run per day (`0 3 * * *`, already configured); Pro can use `*/30 * * * *`.
- `images.remotePatterns` in `next.config.ts` whitelists Unsplash, Cloudinary, Google avatars and
  the Vercel Blob host — add your own CDN host before pasting those URLs into the CMS.
- Connect a **Vercel Blob** store (Storage → Blob → Connect) so admin uploads have somewhere durable
  to live; see [Media & uploads](#media--uploads).
- Vercel builds run `postinstall` (`prisma generate`), so the client is always available.

## Smoke-test checklist

A five-minute pass that exercises the money paths (all verified against a seeded database):

1. `npm run dev` → `/`, `/shop`, `/shop/bundles`, a product page, `/cart`, `/faq`, `/about`,
   `/shipping`, `/returns`, `/privacy`, `/terms`, `/hair-care`, `/gift-cards`,
   `/payment-info`, `/contact`, `/login`, `/register` all render `200`.
2. Shop → filter by texture/length → sort → paginate; open a product, pick a length, add to bag.
3. Cart: change qty, apply a seeded coupon, see the free-shipping threshold behave.
4. Checkout as a guest with **Test payment** → order confirmation page → order appears in
   `/account/orders` and in **Admin → Orders** as `PAID`/`PROCESSING`, variant stock decremented.
5. The confirmation email (or `EmailLog` row) carries the guest account setup link
   (`/guest-setup/[token]`) — open it, set a password, land in `/account`.
6. Admin: change the order to *Dispatched* with a tracking number → customer email + `OrderEvent`;
   "Release expired stock" cancels stale unpaid orders.
7. Admin → Emails: save a template, run a campaign (logged as `SKIPPED` when no provider key).
8. Admin → Products → a product → **Gallery**: drop three images, star the second as primary, edit an
   alt text, then confirm the PDP keeps the order, `/shop` shows the primary shot and the cart line
   uses it too; delete one image and check the file disappears from the store. Upload a banner image
   in Admin → Content → Banners and see it on the homepage hero.
9. Lighthouse/PWA: install prompt appears, offline page loads, `/sitemap.xml` lists products and
   CMS pages.

## Troubleshooting

| Symptom | Fix |
| ------- | --- |
| `Environment variable not found: DATABASE_URL` | Create `.env` from `.env.example` (Prisma reads it from the repo root); on Vercel set the variable and redeploy. |
| `Environment variable not found: DIRECT_URL` (`P1012`) | The Prisma CLI needs it for `validate` / `migrate deploy` / `studio` (`prisma generate` alone does not). Add it to `.env` and to Vercel. |
| Production build fails with *The table `public.Page` does not exist* (or on `/faq`) | The database was empty: `/`, `/faq` and the CMS pages are prerendered at build time. Run `prisma migrate deploy` + `db:seed` against that environment's `DATABASE_URL`, then redeploy. |
| Deployment rejected with *Hobby plans can only run cron jobs once per day* | `vercel.json` must use a daily schedule (`0 3 * * *`) on Hobby, or upgrade the project to Pro. |
| `prisma migrate deploy` fails with *relation already exists* (`P3005`) | The database was created with `db push`. Baseline it once: `npx prisma migrate resolve --applied 00000000000000_init`, then re-run `db:deploy`. |
| `[next-auth][error][NO_SECRET]` or sessions silently drop | `NEXTAUTH_SECRET` is missing or shorter than 32 bytes. |
| Login succeeds then bounces to `/login` | `NEXTAUTH_URL` must match the exact origin (including `https://` in production, no trailing slash). Clear cookies afterwards. |
| Locked out of `/admin` / forgotten admin password | `npm run admin:password -- --email you@domain.com` (add `--create` if the account is gone) rewrites the hash against that environment's `DATABASE_URL`. Existing JWTs stay valid until they expire, so sign out and back in; there is no email-based reset flow. |
| `admin:password` fails with *the URL must start with the protocol `postgresql://`* | A placeholder or stale `DATABASE_URL` is exported in that shell — shell values shadow `.env`. Paste the real pooled URL inside single quotes (`$env:DATABASE_URL='postgresql://…'`, so a `$` in the password isn't expanded), or run `Remove-Item Env:\DATABASE_URL` to fall back to `.env`. |
| "Continue with Google" is missing | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` are unset — the button is hidden by design. |
| Payment tiles are missing at checkout | Stripe/PayPal keys are unset, or no supported method is enabled in your default Stripe Payment Method Configuration. The "Test payment" tile only appears in development. |
| Emails never arrive | `EmailLog` shows `SKIPPED` when no provider key is configured (`RESEND_API_KEY` or `SENDGRID_API_KEY` + `EMAIL_FROM`). Check spam and domain verification too. |
| `/api/cron/expire-orders` returns `401`/`503` | Set `CRON_SECRET` and send `Authorization: Bearer <secret>` (Vercel does this for you). |
| `next/image` returns `400` for a pasted image URL | Add the host to `images.remotePatterns` in `next.config.ts`. |
| Stale service worker after a deploy | Dev builds disable the SW. In production, hard-reload or unregister it (DevTools → Application → Service Workers); the SW is regenerated per build with `cleanupOutdatedCaches`. |
| Types complain about missing Prisma fields | `npm run db:generate` after editing `prisma/schema.prisma`. |
| Order emails sit at `SKIPPED` in `EmailLog` | No provider configured — set `EMAIL_PROVIDER` + `SMTP_*` (or an ESP key) and run `npm run email:check`. |
| `npm run email:check` fails with `535`/`530` | Wrong mailbox password or the server blocked the IP — confirm the mailbox logs in via webmail first. |
| Mail to `contact@` / `orders@` never arrives even though sending works | No **MX** in the *live* zone (or an MX pointed at the web server), so senders have nowhere to deliver even though SMTP login and local delivery are fine. Run `npm run email:check -- --dns`; the records often already exist in the registrar's zone editor but are inert while the nameservers point elsewhere (Vercel for this project) — recreate MX/SPF/DKIM/DMARC plus `A mail` in the live zone. MX must target the provider's relays (`mx*-hosting.jellyfish.systems`); `mail.<domain>` opens port 25 but never greets, so mail to it times out. `550 No Such User Here` from `email:check <address>` means the mailbox is missing; acceptance proves it exists. |
| App mail is spam-filed or rejected with `550 5.7.x` | No **SPF/DKIM/DMARC**. Publish `TXT @ → v=spf1 …` for the SMTP host, the host's `default._domainkey` DKIM record and `TXT _dmarc → v=DMARC1; p=none; rua=mailto:contact@…`, then re-check with `npm run email:check -- --dns`. |
| `next lint` warns that the command is deprecated | Expected on Next 15 — the ESLint config still runs; Next 16 will require the ESLint CLI. |
| Uploads fail with `503` *Image storage is not configured* | No `BLOB_READ_WRITE_TOKEN`: connect a Vercel Blob store to the project and redeploy (or set `MEDIA_PROVIDER=local` for local dev). |
| Upload returns `413` / *Request Entity Too Large* | The file exceeds the 4 MB ceiling or Vercel's ~4.5 MB body cap. Compress the image; `MEDIA_MAX_BYTES` only lowers the limit. |
| Upload returns `422` *Unsupported image* | The bytes are not JPEG/PNG/WebP/AVIF — SVGs and renamed files are rejected on purpose. Re-export as JPG or WebP. |
| Blob upload fails with `403` / *store does not exist* | The token belongs to a different Blob store or a read-only token — reconnect the store and copy the fresh `BLOB_READ_WRITE_TOKEN`. |
| Uploaded images 404 locally after a restart | Dev uploads live in `public/uploads/` (git-ignored). Re-upload, or set a Blob token so files survive restarts. |
| `next/image` rejects a pasted upload URL | Add the host to `images.remotePatterns` in `next.config.ts` (Blob and the seeded CDNs are already whitelisted). |
